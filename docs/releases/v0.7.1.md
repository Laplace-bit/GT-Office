# v0.7.1

## Production Editor And Terminal Colors

### Symptom

The built macOS app rendered both Monaco editor syntax tokens and xterm ANSI output as mostly white text, while the dev server rendered colors correctly. The issue was repeatedly misdiagnosed as terminal environment/ANSI setup because terminal output and editor highlighting failed at the same time.

### Root Cause

The regression was in the production frontend rendering path, not in backend terminal data. A series of fallback fixes added custom xterm `.xterm-fg-*`/`.xterm-bg-*` rules, Monaco foreground/background overrides, startup skeleton styles, lazy shell chunks, and a custom Vite production target. In the built WKWebView app, these changes altered style injection/order and allowed fallback CSS to override xterm and Monaco runtime-generated color rules.

### Fix

The frontend rendering path was converged back to the last known-good `v0.6.2` behavior:

- Let xterm own ANSI color classes and theme application.
- Let Monaco own token color styles through its runtime theme and `.mtk*` rules.
- Restore Monaco environment initialization as a direct startup side effect.
- Remove the startup skeleton/lazy shell chunk path that changed production-only style loading order.
- Remove the custom Vite production target/minify/env dependency settings.

### Regression Guard

If production-only colors regress again, compare against `v0.6.2` before adding color fallbacks. Avoid app-level overrides for xterm `.xterm-fg-*`, `.xterm-bg-*`, `.xterm-rows`, Monaco `.mtk*`, or Monaco editor foreground/background unless a production app build proves the change is safe.
