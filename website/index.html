The differentiator

Agents that work with agents.

While other desktop apps isolate every CLI in its own tab, GT Office ships gto — a communication bus your agents use themselves. Dispatch a refactor to Codex, have Claude review it, get a handover when it's done.

# agent → agent, no human in the loop
$ gto agent send-task --target-agent-id codex \
  --title "Refactor auth module" --markdown task.md
✔ task t_01 dispatched
$ gto agent reply-status --task-id t_01 \
  --detail "review passed, 12/12 tests green"
✔ status delivered to claude-code

FAQ

Questions developers actually ask.

Is GT Office a wrapper that limits what the CLIs can do?

No. GT Office wraps the official Claude Code, Codex CLI and Gemini CLI binaries directly — no abstraction layer sits between you and the tool. Every flag, every permission prompt, every capability stays exactly as the CLI authors designed it.

Which AI coding agents are supported?

Claude Code, OpenAI Codex CLI and Gemini CLI work out of the box. Any terminal-first agent that runs in a shell can be attached to an agent workstation.

How does agent-to-agent communication work?

GT Office ships a companion CLI called gto. Agents call commands like gto agent send-task and gto agent reply-status to dispatch work, report progress and hand over results — a task bus with persistent threads, not copy-paste between terminals.

Does it replace my terminal?

No — it organizes it. Terminals are still real shells with your full PATH and dotfiles. GT Office adds persistence, workspace-scoped state, Git and file surfaces, and multi-agent orchestration on top.

Is it free and open source?

Yes. GT Office is Apache-2.0 licensed, built with Rust, React and Tauri. Releases are free to download on macOS, Windows and Linux.
